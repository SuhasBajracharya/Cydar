# AGENTS.md

Two independent scaffolds, no root tooling, no git repo. No shared build, lint, or test runner — work in one side at a time.

## Layout

- `backend/` — Django 6.1 project, settings module `config.settings`, app package `config/`. No project apps yet (`INSTALLED_APPS` is contrib-only, `urls.py` is admin-only).
- `frontend/` — React 19 + Vite 8, plain JSX (`src/main.jsx` entry). No TypeScript, no test runner.

## Backend

- Deps are pinned in `backend/requirements.txt` (`Django==6.1`, `openai`, `python-dotenv`); install with `./venv/bin/pip install -r requirements.txt`.
- Always run from `backend/` so `config.settings` resolves, using the venv directly (it is not on PATH):
  - `cd backend && ./venv/bin/python manage.py <cmd>`
  - e.g. `./venv/bin/python manage.py runserver`, `./venv/bin/python manage.py migrate`, `./venv/bin/python manage.py test`
- DB is SQLite at `backend/db.sqlite3`. `DEBUG=True`, hardcoded dev `SECRET_KEY`.
- Apps: `targets` (Target / AgentRun / Finding / Scan models + `/api/` JSON views + Django `admin.py` registering all models with list/filter/search/inlines), `agent` (plain package, not a Django app: provider registry + LLM client + system prompt), `recon` (plain package: local nmap/gobuster runner via subprocess, no shell).
- Secrets via `<repo-root>/.env` (see `.env.example`): one `*_API_KEY` per hosted provider (`DEEPSEEK_`, `OPENROUTER_`, `AGENTROUTER_`, `NVIDIA_`, `OPENCODE_` for Zen). Provider list/URLs/defaults live in `backend/agent/providers.py`. Never hardcode or commit keys; `/api/providers/` exposes only configured flags + model lists.
- Local models via Ollama (no key): `ollama` provider in the registry, default URL `http://localhost:11434/v1`, default model `qwen3:8b` (override with `OLLAMA_BASE_URL` / `OLLAMA_MODEL`). Always shows as configured in the picker; requires `ollama serve` running plus `ollama pull qwen3:8b` (any pulled tag works via the picker's "Custom…" field).
- Local recon: `POST /api/targets/<id>/scans/` runs one preset synchronously on the server box — `nmap-fast` (`-T4 -F`), `nmap-services` (`-sV`, standard+), `nmap-scripts` (`-sV -sC`, aggressive only), `gobuster-common` (dir mode vs `https://<domain>`, server-side wordlist; `-k` added when the target has `allow_insecure_tls`). Host is validated (no shell, private RFC1918 allowed for VPN labs, loopback/link-local still refused, ~3 min timeout, output truncated at 30k chars). Timeline deletes: `DELETE …/runs/<id>/`, `…/findings/<id>/`, `…/scans/<id>/` (owner-scoped, confirm in UI).
- Autonomous agent (`agent/loop.py` + `targets/agent_runtime.py` + `targets/agent_views.py`): ReAct loop over `recon/tools.py` (nmap, gobuster dir+vhost, subdomain_enum via crt.sh/cert-SAN/DNS-brute, vhost_enum Host-header fuzzing vs random-host baseline, fetch_many batch triage, http_fetch + header_audit (both accept optional `host_header` for DNS-less vhosts, curl `-H 'Host:'` style), dns_lookup, auth_check, login_wall_probe, trial_signup (opt-in), reflection_test, open_redirect_check, sqli_probe, cors_check, upload_probe — all scope-checked, level-gated, detection-only). Targets have `allow_insecure_tls` (Edit target checkbox, lab/self-signed hosts only) which skips TLS verification in HTTPS tools, cert-SAN pulls, and gobuster. Long enumeration output is digested for history (counts + actionable hits; full output stays on the AgentAction row). Tool args are validated at proposal time (missing/out-of-scope args refused pre-approval with the correct shape; identical repeat refusals escalate to a stop nudge; nameless/malformed ```tool blocks are rejected as parse failures with a `malformed` SSE event carrying the raw payload). Model proposes tool calls via ```tool JSON blocks (works on any provider; `normalize_tool_payload` also accepts `tool`/`tool_name` aliases and single-key wrappers); each step saved as `AgentAction`; final ```report block validated into a `Report` (honest schema: `confirmed` with pasted evidence → `Finding` rows, plus `leads` with exact manual verify steps; evidenceless items are rejected back to the model) + auto-created `Finding` rows. Report grounding: `confirmed` evidence must quote a 40+ char verbatim chunk of the session's recorded tool output, and non-empty `confirmed` with 0 tool calls is rejected (empty `confirmed` + honest `scope_notes` stays legal). No-fence replies escalate (unfenced-report rescue → mandatory-block order → interrupted save at 5). Sessions run in worker threads with SSE events (`…/agent/<run>/events/`: status, thought, tool_call, pending, malformed, approved, rejected, tool_result, report_rejected, budget, report, error, done), modes `semi` (approve/reject + guidance hint per call) and `auto`; budgets default 25 steps / 30 min (`POST …/agent/start/`), stop via `POST …/agent/<run>/stop/`, audit via `GET …/agent/<run>/actions/`, reports via `GET …/reports/`.
- Session auth (Phase 1): operator logs in in their own browser and pastes the session into the target (Edit target → Session auth: bearer/header/cookie + check URL, one slot per host via `AuthCredential` rows with `*.domain` patterns + legacy single slot fallback). `auth_value` is write-only (never in API output); HTTP tools inject it server-side (model never sees it); `auth_check` validates; expiry raises `AuthExpired` → `auth_needed` event pausing semi AND auto for Approve (after paste) / Skip (remembered per host per session). `login_wall_probe` classifies walls; `trial_signup` (aggressive + `allow_self_registration` + `SIGNUP_IMAP_*` mailbox) registers throwaway accounts and saves the session. All stored/emitted strings pass through `recon.tools.redact()`. Plaintext SQLite storage is dev-only.

## Frontend

- `cd frontend && npm run dev` (HMR; `/api` proxies to Django at `127.0.0.1:8000`), `npm run build`, `npm run preview`.
- Lint is oxlint, not ESLint: `cd frontend && npm run lint`. Rules in `.oxlintrc.json`.
- Styling is Tailwind v4 (`@tailwindcss/vite` plugin + `@import "tailwindcss"` in `src/index.css`).
- SPA in `src/App.jsx` (shell + view-state routing only) + `src/api.js` (session-cookie + CSRF fetch wrapper). Screens in `src/pages/` (`Dashboard`, `TargetDetail`), widgets in `src/components/` (`AgentPanel`, `FeedEvent`, `TargetForm`, `ModelPicker`, `LoginForm`, `ui`), pure helpers in `src/lib/` (`session.js`, `styles.js`). One default-export component per file, named after the file. No tests, no typecheck, no formatter configured.
- UI: dark sidebar shell (Overview + per-target nav) with light content. Overview = stat cards (`GET /api/stats/`) + targets table (Open/Run/Edit/Delete). Target create/edit share `TargetForm` in a modal (incl. Allow insecure TLS checkbox for labs); `PUT/DELETE /api/targets/<id>/` (delete cascades). Detail page has anchor-nav section cards: Agent, Plan, Recon, Scans, Reports, Timeline. Agent feed shows the exact attempted tool name on every event (proposal/approval/refusal/malformed with raw payload), with Copy buttons on commands/args and a ⭳ Download log per session (`#seq tool=[name] [status]` + thought/command/args/output/error) for manual follow-up runs.
